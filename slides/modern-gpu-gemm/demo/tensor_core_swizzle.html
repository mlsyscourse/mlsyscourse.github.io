Why Swizzle Helps Tensor Cores

TC needs 16×16 fp16 tiles — swizzle makes each 8×8 sub-tile conflict-free

Step 1: Tensor Core reads 16×16 fp16 from shared memory

A single TC instruction (e.g., mma.sync m16n16k16) needs a 16×16 fp16 tile.

In shared memory, this is 16 rows × 32 bytes/row = 512 bytes.

Step 2: Decompose 16×16 into four 8×8 sub-tiles

Each 8×8 fp16 sub-tile = 8 rows × 16 bytes = 128 bytes = 1 swizzle atom (SWIZZLE_128B).

Step 3: Each 8×8 sub-tile is conflict-free with swizzle

With SWIZZLE_128B, reading any column of 8 elements within an 8×8 atom touches all 8 distinct sectors.

Result: each 8×8 sub-tile reads in 1 cycle.

Total: 16×16 tile = 4 conflict-free reads of 8×8 blocks.

Step 4: Works for any transpose configuration

Whether A is read row-wise or column-wise, the hardware always reads 16×K or K×16 sub-matrices.

These decompose into 8×8 fp16 tiles regardless of orientation.

A transposed: read K×16 → still decomposes into 8×8 tiles

A normal: read 16×K → still decomposes into 8×8 tiles

Swizzle guarantees conflict-free shared memory access for tensor core operations, regardless of transpose.
